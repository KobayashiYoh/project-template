# GIT RULE

## ブランチ戦略

- GitFlow に準ずる
- default ブランチは`develop`

## コミット戦略

- コミットメッセージは日本語で記述すること
- コミットメッセージは必ず prefix をつけること（後述の prefix の項目を参照）
- revert などを考慮してコミットは機能の最小単位で行う
- ファイルの新規作成は基本 1 つずつ行う（ただし、dev/iam.tf と prod/iam.tf や package.json と package-lock.json のような組み合わせは新規作成でもまとめてコミットしてよい）
- コミットの順番は依存関係を考慮する
- コミットメッセージはどんな実装を行なったのか一目でわかるようなものにする（「xx を更新」より「xx のため xx を変更」が望ましい）
- AI エージェントは確認工程削減のため、`add` と `commit` はワンライナーで実施すること

## prefix

| prefix   | 説明               |
| -------- | ------------------ |
| feat     | 機能の追加         |
| fix      | 不具合の修正       |
| docs     | ドキュメントの変更 |
| refactor | リファクタリング   |
| test     | テスト関連         |
| chore    | その他             |

## その他

- API キーやアクセスキーなどの機密情報は Git の差分に含めないこと（.gitignore を用いる）
