# コーディング規約

各フレームワーク・言語共通のコーディングルール

## 原則

- KISS（Keep It Simple, Stupid）原則を厳守すること
- DRY（Don't Repeat Yourself）原則を厳守すること
- YAGNI（You Aren't Gonna Need It）原則を遵守すること
- PIE（Prefer Interfaces to Implementations）原則を厳守すること
- SLAP（Single Level of Abstraction Principle）原則を遵守すること
- OCP（Open/Closed Principle）原則を遵守すること
- 名前重要の原則を遵守すること
- 単一責任の原則を厳守すること

## 可読性・保守性

- if 文の{}を省略しないこと
- `&&`や`||`が必要な複雑な条件式がある場合は説明変数を用いること
- 肥大化（目安 80 行）したコードは別ファイルなどに分けること
- ネストの多重化を避けること（早期 return や早期 throw を使用）
- ビジネスロジックと関係ない汎用処理は utils に切り分けること
- 不要になった処理はコメントアウトではなく削除すること

## コメントアウト

- 原則としてコードにコメントアウトを記述しないこと
- コードの意図はコメントアウトではなく命名などで伝えるようにすること（How コメントの使用は避け、Why コメントのみコメントアウトを残す）
- コメントアウトは日本語で記述すること
- 関数、クラス、インターフェース、エクステンションにはドキュメントコメントを記述すること
- 変数、フィールド、コンストラクタにはドキュメントコメントを記述しないこと
- ドキュメントコメント以外の通常コメントアウトは原則書かない

## ドキュメント

- ディレクトリの追加や変更を行った際はディレクトリ構成のドキュメントも更新すること
- 不要になった`.gitkeep` は削除すること

## テスト

- グループ名やテスト名などは英語ではなく日本語で記述すること
- コードを追加・修正したら、テストコードも追加・修正すること

## セキュリティ

- 機密情報は Git の差分に含まないこと
- 機密情報をクライアントサイドに保管しないこと（`.env` を`.gitignore` に追加してクライアントサイドで保管するのではなく、サーバーサイドに保管すること）
- GitHub Actions の Secrets などの機密情報を CI/CD のログ出力に含まないこと（必ずマスクすること）
